# teller

저축은행 통합단말 구조 학습용 프로젝트.  
창구 업무를 전문(電文) 기반으로 구현했다.

## 기술 스택

- Java 21 / Spring Boot 4
- MyBatis / H2 (Oracle 호환 모드)
- BCrypt (비밀번호 해시)
- Maven
- HTML + Vanilla JS (ES5 스타일)

## 실행

```bash
mvn spring-boot:run
```

## 패키지 구조

```
com.study.teller
├── common       전문 유틸, 예외, 검증, 세션, 암호화, 공통응답
├── vo           요청/응답 데이터 객체
├── msg          전문 생성(pack) / 해석(unpack)
├── sender       계정계 통신 (스텁)
├── service      업무 로직
├── mapper       DB 접근
└── controller   요청 진입점
```

## 처리 흐름

```
화면(JS)
  ↓ JSON
Controller        ApiResponse로 감싸서 반환
  ↓
Service           검증 → 공통부 → 이력저장 → 응답확인
  ↓                            ↓
Msg               pack/unpack   Mapper → 단말 DB
  ↓
MsgSender         거래코드 분기 → 원장 조회/변경
```

한 거래의 처리 순서는 항상 같다.

```
set → pack → 전송 → unpack → get
```

## 전문 구조

고정길이 문자열. 공통부 + 개별부로 구성된다.

```
[전문길이 4][공통부 35][개별부 가변]
```

**공통부** — 거래코드, 기관코드, 영업점코드, 직원번호, 거래일자, 거래시간

**필드 채우기**

| 타입 | 정렬 | 패딩 |
|---|---|---|
| N (숫자) | 우측 | 좌측 0 |
| AN (문자) | 좌측 | 우측 공백 |

길이는 바이트 기준으로 센다. EUC-KR에서 한글은 2바이트.

## 구현한 업무 규칙

**영업일**  
거래일자는 달력 날짜가 아니라 영업일. 주말·공휴일이거나 마감 후면 익영업일로 처리된다.

**마감**  
직원별 시재 마감 → 전원 완료 확인 → 영업점 마감. 시재 차액이 있으면 마감할 수 없다.

**권한**  
메뉴 노출 / 화면 진입 / 서버 검증의 3중 구조. 화면 검증은 우회 가능하므로 서버가 최종 방어선.

**취소**  
원거래를 지우지 않고 반대 거래를 생성한다. 이력에 두 건이 남는다. 거래번호로 원거래를 특정한다.

**해지**  
계좌 행을 삭제하지 않고 상태만 `02` 로 바꾼다. 이력 참조와 법적 보존, 취소 가능성 때문.

**이체**  
출금과 입금이 한 트랜잭션. 하나라도 실패하면 둘 다 롤백된다. 이력은 출금·입금 두 건으로 남는다.

**이력**  
성공·실패 모두 저장한다. 이력 저장이 실패해도 거래는 성공 처리하고 로그만 남긴다. 계정계 거래는 롤백되지 않기 때문.

## 보안 처리

| 대상 | 방식 | 위치 |
|---|---|---|
| 직원 비밀번호 | BCrypt 해시 | `PasswordUtil` |
| 전문 로그 | 마스킹 | `MsgSender.mask` |
| SQL | `#{}` 바인딩 | Mapper XML |
| 시스템 오류 | 상세 메시지 은닉 | `GlobalExceptionHandler` |

`CryptoUtil` (AES 양방향 암호화)은 만들어두었으나 전문에는 적용하지 않았다. 계좌 비밀번호는 계정계가 검증해야 하므로 해시가 아닌 양방향 암호화가 필요하다.

## 학습용 단순화

실무와 다르게 처리한 부분.

- 계좌 비밀번호를 평문으로 전송 (실무: 암호화 또는 핀패드)
- `CryptoUtil` 의 암호화 키가 소스에 하드코딩 (실무: HSM 또는 키관리 시스템)
- 계좌번호 채번이 MAX+1 (실무: 시퀀스, 검증번호 포함)
- 영업일·마감이 지점 구분 없음 (실무: 기관+지점별 관리)
- 서버 기동 시 직원 비밀번호를 초기화 (실무: 등록 시점에 해시)
- 공통부 채우기가 Service마다 중복 (실무: 공통 유틸 또는 인터셉터)
- MsgSender가 계정계를 흉내내는 스텁
